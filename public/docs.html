CareCircle · MCP spec 2025-11-25

The care layer, as an MCP server

CareCircle tracks what needs to happen for someone being cared for, and who is responsible for it — and exposes that as 25 MCP tools an AI assistant (Alexa+, or any MCP client) calls. Real events flow in from real accounts and devices; every one enters as a guess a human confirms, never a fact written by a machine.

Self-hosted MCP

Streamable HTTP, spec 2025-11-25, live on AWS App Runner. The compliant Alexa+ surface.

Real connections

Calendar, Gmail, Ring, Bee, WhatsApp, Telegram — network at the edges, a pure core.

Provenance-first

Known ≠ assumed. Every claim carries where it came from; a guess stays a guess until confirmed.

Architecture

One spine runs the whole system: events are the only source of truth, obligations are what folds out of them, and ownership is the stage where care actually succeeds or slips.

EVENTS ──► OBLIGATIONS ──► OWNERSHIP (append-only) (folded from events) (who is responsible) A Care Gap = a failure at the ownership stage: real work with no owner, an expected record that is missing, or something now past its time.

Network at the edges, pure core

Every connector follows the same shape, so the store-touching logic is always testable without a socket:

<x>ConfigFromEnv → fetch<X> → sync<X> → run<X>Sync (reads env) (only network) (pure, idempotent) (wires them)

Inbound webhooks (Ring, WhatsApp, Telegram) and pollers (Calendar, Gmail, Bee) all land in the same store the MCP tools read and write — a reply over Telegram travels the exact path a spoken one does.

The trust model

The thesis of the whole system: a machine never writes a fact. A real event from any source enters as a signal → an INFERRED item → a human confirms → a fact. Evidence is not a verdict.

Provenance — how sure we are of an obligation

CONFIRMED a person stated it   INFERRED the system guessed it — never counted until confirmed   NOT_LOGGED nothing was recorded — not "it didn't happen"

Confidence — how sure we are of an event

Deliberately separate from provenance. An event can be observed (a sensor saw it) while the obligation it feeds is still only INFERRED.

  • observed — a sensor saw it happen
  • reported — a person said it happened
  • inferred — the system derived it from other events
  • confirmed — a person definitively decided or acted

The rule that never bends: the system only knows what was recorded. An absent record is never evidence that something didn't happen — no tool ever says a person failed to do something.

HTTP endpoints

The MCP server (carecircle-mcp) serves the protocol plus the inbound webhooks. Webhooks that verify a signature are mounted before the JSON parser so the HMAC is computed over the raw bytes.

MethodPathPurpose
POST/mcpThe MCP endpoint (Streamable HTTP, spec 2025-11-25).
GET/healthHealth check (App Runner probes this).
POST/ring/webhookRing events, HMAC-verified → INFERRED note.
GET POST/whatsapp/webhookGET verifies the subscription; POST takes signed inbound replies (X-Hub-Signature-256).
POST/telegram/webhookInbound replies, gated by the secret-token header. Works in a family group.
GET POST/oauth/*OAuth 2.1 + PKCE (authorize/token/register) — present only when a signing secret is set.

Data doors

Real accounts and devices. Each is either an inbound webhook or a polled connector; the outbound reply channel sits behind one Notifier seam. Ask get_connections for live status.

DoorDirectionHow it connects
Google Calendarpoll · in + write-backGoogle OAuth; real events → INFERRED appointments; write back to the shared calendar.
Gmailpoll · inboundGoogle OAuth; a matching appointment/refill email → INFERRED item.
Ringwebhook · inboundHMAC-verified webhook → INFERRED note. Needs a real Ring device to emit events.
Beepoll · inboundGET /v1/facts + /v1/todos (Bearer); a todo → PROPOSED obligation, a fact → observation. Always logistical.
WhatsAppwebhook · in + outBusiness Cloud API; outbound asks, signed inbound replies. Sender is a Business line (Meta's rule).
Telegramwebhook · in + out liveBot API; outbound asks (DM or family group), secret-token-gated inbound replies. No verification wall.

Why doors aren't tools. A webhook is an inbound push — the agent can't "call Telegram to check for replies." So the transport lives at the edge, but the result is fully visible and actionable through MCP tools, and the connection status is exposed via get_connections.

Identity & permissions

Who is speaking is established by the session credential — never by the conversation. The production resolver is firstOf(oauthTokens, staticTokens): an OAuth token resolves first, else a mapped static token. With self-signup on, an authenticated-but-unmapped caller becomes a bootstrap principal who can create their own circle.

Roles & capabilities

RoleCan do
primary_caregiverThe full circle: assign, manage members and meds, everything below.
caregiverLog, claim, respond, ask, read — the day-to-day of care.
helperA paid aide: scoped to the work in front of them (their own obligations).
care_recipientLog things about themselves; read their own circle.

Every tool checks the caller's capability first; households are isolated (an adversarial suite guards the boundary).

Deployment

Two AWS App Runner services share one ECR :latest image, built in the cloud by CodeBuild from git archive HEAD — so commit before deploying.

ServiceHostRole
carecircle-mcpypq2dfq2p7…The MCP server + webhooks + the agent heartbeat.
carecircle-simkrqi2tpsif…The Alexa+ console UI; proxies to the MCP server.
AWS_PROFILE=conductor  source .env
bash infra/deploy-mcp.sh          # build image + update-service (env)
aws apprunner start-deployment …  # force the new image to pull

Two gotchas that have bitten before.

· An env change is an update-service; a new image needs an explicit start-deployment — do both, or the routes 404 on a stale image.

· update-service replaces the whole env map and requires AuthenticationConfiguration.AccessRoleArn — derive from the live config so secrets and the ECR access role survive.

Testing

The suite runs on the Node test runner (not vitest):

npx tsx --test "src/**/*.test.ts"     # 405 tests
npx tsc --noEmit                       # typecheck

Domain logic is pure and network-free, so most tests need no mocks; connectors are tested against recorded real payloads as fixtures.

Using the UI

The console is an MCP client: pick who you are, talk or type, and watch the board react with provenance chips. Live surfaces:

PathSurface

Two endpoints back the console: POST /api/say (natural language → planner) and POST /api/act (call one tool directly with exact args, for scripted demos).
